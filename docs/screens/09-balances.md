# 09 · Balances (Expenses tab)

Figma node `4048:16899`. Built in `src/screens/Balances.tsx`.

Same trip-screen nav/chrome as 02 (back, buddy stack + add), but the content is the Expenses tab:
"You're owed" card, netted settle-up list, full expense ledger. `BottomBar` with `activeId="expenses"`
— no new component needed, it already supports either tab active.

## Data flows from domain, not copy
Every number on this screen traces back to `src/domain/split.ts` and `src/domain/netting.ts` via
`src/data/expenses.ts`:
- `balanceAfterDinnerById.ari` → the €130 headline.
- `openingBalanceCents.ari` → "was −€30 before dinner" (rendered with a plain hyphen, not Figma's
  typographic minus — the only intentional pixel deviation on this screen).
- `settleTransfers` → both the 5 settle-up rows **and** the "Sven, Bea and Kofi pay you. Ren and
  Mira pay Nic." sentence, which is generated by grouping transfers by `toId` (`owedBySentence()`
  in the screen file), not hand-written — it would relabel itself correctly if the balances ever
  changed.
- `dinnerBill.totalCents` / `dinnerShares.ari` → the toast's "€190" and "+€160".

## New: the expense ledger
`src/data/expenses.ts` gained `expenseLedger`: 5 day-groups, 14 historical entries + today's dinner
(15 total, €1,284) — content that only exists in this Figma frame, not in `PRODUCT_SPEC.md`, so it's
transcribed as flat presentational data rather than derived (the per-item payer/sharer breakdown
for e.g. "Surf lesson, Caparica · Paid by Mira · 4 of you" isn't specified beyond what's shown, so
there's nothing to compute it from). Today's dinner entry is the one exception — it pulls
`dinnerBill`/`dinnerShares` live so it can't drift from 07/08's numbers. Verified the 15 amounts
sum to exactly 128400 cents before committing them.

**Note found in the source design:** the itinerary card on 02 lists Pastéis de Belém at €18, but
this ledger has it at €28 (share €4,67 = 28/6). Both numbers come straight from Figma — this is a
pre-existing inconsistency in the design file between two different mockup contexts, not something
introduced here. Left as-is per "if Figma and this file disagree, Figma wins"; flagging it here
since a future pixel-diff might otherwise look like a build error.

## New domain helper: `formatEurosAuto`
Added to `src/domain/money.ts` after noticing the ledger's "your share" line mixes whole-euro
amounts ("your share €30") and fractional ones ("your share €4,67") depending on whether the item
divided evenly — Figma isn't applying one fixed decimal rule, it's just not printing ",00" when
there's nothing after the comma. `formatEurosAuto` reproduces that: whole euros when `cents % 100
=== 0`, `formatEurosWithCents` otherwise. Covered by `money.test.ts`.

## Gotchas found while building
- `formatEuros` didn't group thousands before this screen (nothing needed it yet) — "€1,284" was
  rendering as "€1284". Fixed with `toLocaleString('en-US')` and added a test.
- The transfer-row arrow (`imgIcon2` in this frame's export) is the same path as the existing
  `arrow-right.svg`, just 14px and `Ink/Secondary` instead of 20px white — reused via the `Icon`
  `color` prop rather than exporting a duplicate.
